# Guitar 콘텐츠 작성 안내

곡 파일은 `content/guitar/songs/<artist-id>/<song-id>.chopro`에 둡니다. ID는 소문자 영숫자와 단일 하이픈만 허용합니다. 두 ID는 공개 URL `<artist-id>--<song-id>`를 만들며, 파일 이름 변경은 공개 URL 변경입니다.

새 파일에는 다음 필드를 선언합니다.

```chopro
{title: 곡 제목}
{artist: 표시할 아티스트}
{key: G}
{capo: 0}
{meta: added 2026-10-09}

{start_of_verse: Verse 1}
[G]코드와 [D]가사를 함께 씁니다
{end_of_verse}
```

`title`, `artist`, `key`는 필수이며 `capo`는 생략하면 0입니다. 조성은 A~G, 선택적 한 개의 `#`/`b`, 선택적 단조 `m`을 지원합니다. `added`와 `updated`는 선택값이며 `YYYY-MM-DD` 형식입니다. `tag`는 여러 번 쓸 수 있습니다.

지원 문법은 이 프로젝트의 ChordPro 부분집합입니다. `[C]` 인라인 코드, 가사·코드만 있는 줄·빈 줄, verse/chorus/bridge 구역, `#` 소스 주석, `{comment: ...}` 연주 안내, `[*...]` 조옮김 제외 주석을 지원합니다. Metadata는 `{title: ...}` 또는 `{meta: title ...}` 형식으로 씁니다.

`[N.C.]`는 **No Chord**, 즉 해당 가사 구간에 연주할 코드가 없다는 뜻의 의도적인 표기입니다. 별도의 `no-chord` 토큰으로 보존하고 조옮김과 운지 조회에서 제외합니다. 미지원 코드 경고를 만들지 않습니다. 다른 미지원 표기는 원문과 위치별 diagnostics를 유지하며 공개 화면에서는 같은 메시지를 한 번만 표시합니다.

## 악보 읽기 화면

Guitar `/`는 `/songs`로 영구 리디렉션합니다. 목록은 블로그의 44rem 읽기 폭과 공통 서체·색상·간격·wordmark·Footer를 사용합니다. 악보는 최대 52rem이며 기본 카포/조성은 원본 metadata를 따릅니다.

좁은 화면에서는 원문 행 내부를 강제로 줄바꿈하지 않습니다. 긴 행을 악보 영역 안에서 가로로 스크롤하여 코드와 가사 문자의 대응을 보존합니다. 악보 영역은 키보드로도 스크롤할 수 있습니다. 데스크톱(70rem 이상)은 왼쪽 sticky 설정·가운데 악보·오른쪽 sticky 운지법을 사용합니다. 좁은 화면의 설정은 악보 위에서 펼치고 접는 일반 문서 영역이며, 모달과 하단 고정 툴바를 사용하지 않습니다. 불필요한 문서 끝 spacer와 끝의 빈 원문 행도 표시하지 않습니다.

코드명은 항상 보입니다. 운지는 hover/focus/tap으로 확인합니다. 데스크톱에서는 오른쪽 영역이 갱신되고 모바일에서는 배경을 가리지 않는 작은 inspector를 표시합니다. Escape로 선택을 해제하고 닫기 버튼은 악보 영역으로 포커스를 돌립니다. 기존 일반 코드 60종과 2개 slash form을 보존하고, 현재 악보의 누락된 slash form 6개를 추가했습니다. 나머지는 표준 튜닝·모든 구성음·최저 MIDI bass·4프렛 폭/최대 4개 눌린 현 조건으로 한정된 탐색을 수행하며, 계산과 검증이 성립하는 운지만 표시합니다. 일부 복잡한 코드는 완전한 형태를 찾지 못할 수 있으며 생략음을 정확한 코드처럼 표시하지 않습니다. 손 크기/권장 손가락/실제 연주 난이도까지 보증하는 데이터는 아닙니다.

## 카테고리, 가사 표기, 커버 프리셋

- `{meta: tag J-Pop}`처럼 기존 tag를 선언하면 목록에서 실제 태그만 카테고리로 표시합니다. 검색과 카테고리 필터는 함께 적용됩니다. 비어 있는 장르 섹션이나 임의 분류는 만들지 않습니다.
- `content/guitar/readings/<artist-id>--<song-id>.json`은 선택적인 읽기 보조 자료입니다. `segments`는 ChordPro의 **정확한 segment.text**를 키로 하며 `romaji`/`korean` 값을, `english`는 가사 한 행의 전체 text를 키로 영어 뜻을 가집니다. 발음/뜻은 공식 번역이 아닌 참고용입니다. 현재 Vaundy 곡에 이 자료를 추가했습니다.
- 데이터가 있는 곡에서 원문/Romaji/English/한글 발음을 선택할 수 있습니다. 발음은 원래 코드 경계를 유지하며, 영어 뜻은 어순 차이 때문에 코드 위치에 억지로 배치하지 않고 원문 아래 표시합니다. 데이터 없는 곡은 원문만 제공합니다. 원문과 보조 자료가 어긋나면 catalog/build에서 실패하므로 함께 편집해야 합니다. 로컬 에디터는 현재 이 JSON의 편집 UI를 제공하지 않습니다.
- 내 커버 프리셋은 커버 이름, 선택적 http(s) URL, 조옮김, 카포, 실음 조성을 곡마다 최대 20개까지 해당 브라우저에 저장합니다. 현재 설정을 저장하고 항목을 눌러 복원하거나 삭제할 수 있습니다. 기기/브라우저 동기화나 공개 공유는 하지 않습니다. 저장 차단 시 실패를 표시합니다. 기존 곡 설정 저장 키는 변경하지 않았습니다.
- 헤더의 slash 표기를 없애고 악보 탐색 링크를 사용합니다. 테마 선택은 Blog와 같은 current-trigger 클래스 및 눈/별 문구를 사용하며 자동(System) 선택을 유지합니다. Footer 구분선 폭을 헤더와 맞춥니다.

곡 상세는 빌드 때 정적으로 생성됩니다. 잘못된 metadata, 섹션 구조, 괄호, slug는 빌드를 실패시킵니다. 미지원 directive와 코드는 원문을 보존하고 경고합니다. 조옮김·튜닝·TAB·grid 같이 음악 해석을 바꾸는 미지원 기능은 게시 오류입니다. HTML과 스크립트는 실행하지 않습니다.

가사와 악보를 공개하기 전에 직접 작성했거나 게시 허가를 받았는지 확인하세요. 공개 테스트 곡 `저녁 산책`은 사용자 요청으로 삭제했습니다. 에디터 검증용 곡은 테스트의 임시 디렉터리에서만 생성합니다.

## 로컬 편집기

저장소 루트에서 pnpm guitar:editor를 실행하고 http://127.0.0.1:4174를 엽니다. 곡 목록에서 파일을 열거나 새 곡을 만들고, metadata 입력과 ChordPro 원문을 편집하면 같은 공개 파서와 뷰어로 미리보기를 확인할 수 있습니다. 줄/열이 표시된 오류가 남아 있으면 저장할 수 없고 경고는 확인 후 저장할 수 있습니다.

저장 경로는 artist-id/song-id.chopro 형식만 허용합니다. 기존 파일은 읽은 뒤 다른 변경이 있으면 409 충돌로 저장을 거부하므로 최신 파일을 다시 여세요. 이 도구는 loopback 개발 서버에서만 제공되며 production Next 앱에는 읽기/쓰기 endpoint가 포함되지 않습니다.

## 운영 연결 체크리스트

운영 연결은 현재 Cloudflare DNS와 Vercel 프로젝트의 실제 상태를 확인한 뒤 진행합니다. 저장소 선언만 보고 기존 레코드가 없다고 가정하지 않습니다.

1. Cloudflare에서 `guitar.hodako.dev`의 기존 DNS 레코드, proxy 상태, TLS 설정을 확인하고 Vercel 프로젝트에 해당 도메인이 이미 연결되어 있는지 확인합니다.
2. DNS 레코드가 없을 때만 Pulumi에 기존 블로그와 일관된 Guitar CNAME을 선언합니다. 이미 있으면 소유권과 현재 설정을 대조한 다음 Pulumi 관리 상태를 맞춥니다.
3. `infra/pulumi` 타입 검사와 `pulumi preview`에서 변경 대상이 Guitar 레코드로 한정됐는지 확인한 후 적용합니다. 기존 레코드 삭제·교체가 계획에 나타나면 진행을 멈추고 상태를 먼저 정리합니다.
4. Vercel 도메인 검증을 마치고 DNS 전파와 TLS 인증서를 확인합니다. 두 호스트가 올바른 사이트를 반환하는지, 응답 Host가 유지되는지, 블로그와 Guitar 응답이 캐시에서 교차 노출되지 않는지 점검합니다.
5. Guitar 홈·목록·상세·canonical·robots·sitemap과 블로그 ko/en·글·Records·관리자·댓글·조회수 경로를 smoke test합니다. 모바일 Safari/Chrome, 터치·회전·dialog·스크롤과 실사용 성능 목표도 별도로 측정합니다.

운영 도메인 인증과 Cloudflare/Pulumi 자격 증명이 제공되지 않은 작업 환경에서는 위 단계를 실행하지 않습니다. 확인 전에는 DNS 선언을 추가하거나 운영 배포를 적용하지 않습니다.
